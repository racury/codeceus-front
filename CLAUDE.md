# codeceus-front (frontend)

SvelteKit site for competitive programming: problems, problemsets, competitions, roadmaps, ranking and profiles. Code is judged by the Rust backend in `../codeceus`. Git repo `racury/codeceus-front` (branch `main`). Cross-project notes and the full dependency version table are in `../CLAUDE.md`.

## Project Configuration

- **Language**: TypeScript 6.0.3. **Stay on 6.x**: svelte-check, SvelteKit and typescript-eslint don't support TS 7 yet.
- **Package Manager**: pnpm (lockfile v9). The local dev toolchain is Node 26.10.0 and pnpm 12.4.1 (via corepack). Run pnpm from PowerShell, because the shim breaks under Git Bash.
- **Adapter**: `@sveltejs/adapter-node` 5.5.7. `pnpm build` writes a standalone server to `build/`.
- **Add-ons**: prettier, eslint, tailwindcss, drizzle, better-auth, mcp
- **Locked core versions**: svelte 5.57.1, @sveltejs/kit 2.70.3, vite 8.3.1, tailwindcss 4.3.3, bits-ui 2.19.3 / shadcn-svelte 1.7.0, sveltekit-superforms 2.30.2 / formsnap 2.0.1, drizzle-orm 0.45.3 / drizzle-kit 0.31.11, postgres 3.4.9, better-auth 1.7.6 + `auth` CLI 1.7.6, @xyflow/svelte 1.7.0, @types/node 26, dotenv 18, prettier-plugin-svelte 4

## Commands

```bash
pnpm install
pnpm dev
pnpm build          # works without any env vars (see "Build" below)
pnpm start          # node --env-file-if-exists=.env build
pnpm check          # svelte-kit sync + svelte-check
pnpm lint           # prettier --check + eslint
pnpm format
pnpm db:start       # compose.yaml: Postgres 18 on :5432 (podman compose / docker compose)
pnpm db:push        # sync schema.ts to the DB (primary workflow; no drizzle/ migrations dir exists yet)
pnpm db:studio
pnpm auth:schema    # regenerate src/lib/server/db/auth.schema.ts after editing auth.ts (runs the `auth` CLI; needs DATABASE_URL)
pnpm db:recalculate-ratings
pnpm tsx src/lib/server/db/seed.ts               # sample data (seed-basic.ts = smaller set)
pnpm tsx src/lib/server/db/make-admin.ts <email> # promote a user to role 'admin'
```

There is no test runner (no vitest or playwright). `pnpm check` and `pnpm lint` are the automated checks, and **both must stay clean**: they report 0 problems as of 2026-09-27.

## Conventions

- Runes mode is **forced** for all project files (`svelte.config.js`). Use `$state`, `$derived`, `$effect` and `$props`, never `$:` or `export let`. For local state that starts from props and resets when they change, use a writable `$derived` (see `settings/profile`, `problems/[id]/edit`), not `$state` plus a syncing `$effect`.
- Internal links and `goto()` go through `resolve()` from `$app/paths` with the route id, e.g. `resolve('/problems/[id]', { id: String(p.id) })` (params are strings). ESLint's `svelte/no-navigation-without-resolve` enforces this. The shadcn `Button` just forwards `href`, so resolve before passing it in.
- Every `{#each}` block needs a key (`svelte/require-each-key`): use the row `id`, or `problemId`/`categoryId` for join rows, or `token` for testcase results.
- The backend is called only from server code (`+page.server.ts`, `+server.ts`, `$lib/server/*`), never from the browser. Never return a raw backend submission to the client: it contains the testcase's `stdin` and `expected_output`, which leaks hidden testcases.
- Authorization is checked inline with `locals.user?.role === 'admin'` in server loads and actions. Every new admin page must do the same check in **both** `load` and each action.
- Solved-problem state comes from `solved_problems`, not from `submissions` (which also holds failed attempts). Insert into it with `.onConflictDoNothing()`, because concurrent polls race. Call `recalculateUserRating` only after that write has committed; it reads through its own connection.
- "Replace the whole set" writes (testcases, roadmap graph) run delete + insert inside `db.transaction`.
- Styling uses Tailwind v4 through `@tailwindcss/vite`. Theme tokens live in `src/routes/layout.css`, and there's no `tailwind.config`. Merge classes with `cn()` from `$lib/utils`.
- Forms use sveltekit-superforms + formsnap. No validation library (zod, valibot, etc.) is installed. Choose and add one on purpose if a form needs a schema.
- Line endings are LF everywhere (`.gitattributes`: `* text=auto eol=lf`), matching prettier.

## Environment

Copy `.env.example` to `.env`. It covers `DATABASE_URL` (front DB on :5432), `ORIGIN` (`http://localhost:5173`), `CODECEUS_URL` / `CODECEUS_TOKEN` (= backend `AUTH_TOKEN`), `BETTER_AUTH_SECRET`, and the optional `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`.

- **Dev** (`pnpm dev`): Vite loads `.env`.
- **Production** (`pnpm start`): adapter-node does **not** read `.env` itself; the `start` script passes it with `--env-file-if-exists`. Set `ORIGIN` to the public URL and `PORT` if not 3000.
- **CLI scripts** (seeds, make-admin, recalculate-ratings) load `.env` themselves with `import 'dotenv/config'` as their **first** import.

## Build

`pnpm build` needs no secrets. `src/lib/server/db/index.ts` only requires `DATABASE_URL` outside SvelteKit's `building` phase, since postgres.js connects lazily. `auth.ts` uses a throwaway secret while `building`, and `BETTER_AUTH_SECRET` is still required at runtime.

Never `import 'dotenv/config'` from `db/index.ts` or any other module the app imports. adapter-node bundles dotenv's CommonJS entry into the ESM server build, and `node build` then crashes with `require is not defined`.

## Known state / gotchas

- **Build scripts under pnpm 12:** these are allow-listed in `pnpm-workspace.yaml` under `allowBuilds` (currently `esbuild` and `@tailwindcss/oxide`). pnpm 12 ignores the old `onlyBuiltDependencies` key. If a new dependency brings a build script, `pnpm install` fails with `ERR_PNPM_IGNORED_BUILDS`. Add it to `allowBuilds` with `true`, or with `false` if the script isn't needed.
- **The Better Auth CLI is the `auth` package.** `@better-auth/cli` is deprecated. Keep `auth` and `better-auth` on the same version (both `~1.7.6`).
- **Hidden testcases and stdout:** the problem page still shows `stdout`/`stderr` of a failing _hidden_ testcase. A program can therefore print its input and reveal hidden tests. Hiding that output is a product decision that hasn't been made yet.
- The backend has its **own** DB on :5433. Never point this app's `DATABASE_URL` at it.
- `GEMINI.md` was deleted from the working tree (it's still in git history) and is not restored.

You are able to use the Svelte MCP server, where you have access to comprehensive Svelte 5 and SvelteKit documentation. Here's how to use the available tools effectively:

## Available Svelte MCP Tools:

### 1. list-sections

Use this FIRST to discover all available documentation sections. Returns a structured list with titles, use_cases, and paths.
When asked about Svelte or SvelteKit topics, ALWAYS use this tool at the start of the chat to find relevant sections.

### 2. get-documentation

Retrieves full documentation content for specific sections. Accepts single or multiple sections.
After calling the list-sections tool, you MUST analyze the returned documentation sections (especially the use_cases field) and then use the get-documentation tool to fetch ALL documentation sections that are relevant for the user's task.

### 3. svelte-autofixer

Analyzes Svelte code and returns issues and suggestions.
You MUST use this tool whenever writing Svelte code before sending it to the user. Keep calling it until no issues or suggestions are returned.

### 4. playground-link

Generates a Svelte Playground link with the provided code.
After completing the code, ask the user if they want a playground link. Only call this tool after user confirmation and NEVER if code was written to files in their project.
